# 1 本書の位置づけ

## 1.1 目的
要件からコードの関数、テスト結果まで追跡できるよう、設計図書で使う全IDの書式・定義元図書・附番手順を一意に定める。

## 1.2 記述対象

- ソースコードへの追跡タグ

# 2 ID書式の共通規則

## 2.1 基本書式
1. 書式は `<種別>-<連番>` または `<種別>-<副種別>-<連番>` とする。種別は英大文字2〜5字、副種別は英大文字2〜4字とする。
2. 連番はゼロ埋め3桁とし、999を超えた場合のみ4桁とする。
3. 子IDは親IDの後ろに接尾辞を付けて作る。接尾辞は [[#3.2 子IDの接尾辞|子IDの接尾辞]] に従う。
4. ID文字列は英大文字・数字・ハイフンのみで構成し、空白・全角文字を含めない。

## 2.2 一意性と不変性
1. IDはリポジトリ全体で一意とする。
2. 附番したIDの意味変更と再利用を禁止する。
3. IDの定義は定義元図書の1か所のみとする。他図書は定義せず、Obsidianリンクで参照する。

## 2.3 廃止手順
1. 廃止するIDの定義は削除しない。
2. 属性表の `状態` を `Deprecated` とし、`後継ID` に後継のIDを記載する。後継がない場合は `なし` と記載する。

## 2.4 附番手順
1. 定義元図書で、同一種別・同一副種別の既存最大連番に1を加えた連番を採る。
2. 欠番を再利用しない。
3. 分類コードが必要な種別で台帳に未登録のコードを使う場合は、先に [[#4.1 分類コード台帳|分類コード台帳]] へ追加する。

## 4.2 分類コードの転用
他プロジェクトへ転用する場合は、本書の [[#4.1 分類コード台帳|分類コード台帳]] の表のみを差し替える。他の章は変更しない。

## 4.3 ソースコードへの追跡タグ
1. 関数・クラス・プログラムの実装箇所の直上コメントに `@spec <ID>` を記載する（例: `@spec FN-SRV-001`）。
2. テストコードのテスト単位の直上コメントに `@test <ID>` を記載する（例: `@test TEST-UT-004`）。
3. 1つの実装に複数のIDが対応する場合は、IDを空白区切りで並べる。
4. タグの付与と機械検査は後続PBI（PBI-018）で実施する。
