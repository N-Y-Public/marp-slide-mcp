# 1 本書の位置づけ

## 1.1 目的
生成AIが何回どこに追記・削除しても、設計図書が同じ構造・同じ品質に収束するよう、図書体系と記述構文を一意に定める。プロジェクト固有の内容を含めず、他プロジェクトへ転用できる形とする。

## 1.2 記述対象
- 図書体系と各図書の記述責務
- 全図書共通の記述構文（Frontmatter、見出し番号、第1章、ID定義記法、文体、禁止語）
- リンク規約
- 入出力仕様の意味と形式の分離規則
- 雛形と構文検査器の適用範囲

## 1.3 記述対象外と参照先
- ID種別、書式、附番手順、分類コード: [[04_id_numbering_rules#3.1 ID種別と定義元図書|ID種別と定義元図書]]
- 図書別の章構造と属性表の列定義: `docs/templates/tpl_*.md`（各雛形が正本）
- 実装言語別のコード記述規約: コーディング規約

## 2.2 記述責務の排他規則
1. 各図書は「記述対象」に属する内容だけを書く。
2. 他図書の記述対象に属する内容を説明上示したい場合は、本文へ転記せず、正本図書の該当見出しへObsidianリンクを張る。
3. 追跡表は `DOC-RTM-001` のみに置く。他図書に同じ表を置かない。
4. 図書末尾に関連図書リンクの章を設けない。関連図書は各図書の第1章 [[#3.3 第1章の固定構造|固定構造]] の「記述対象外と参照先」に集約する。

## 2.3 該当なし図書の扱い
プロジェクトに該当しない図書は作成しない。索引の図書一覧に「該当なし」と理由を1行で記載する。

# 3 共通記述構文

## 3.1 Frontmatter
全図書の先頭に、次の9キーを必ず記載する。

| キー | 値の書式 |
| :--- | :--- |
| `id` | 文書ID（`DOC-<階層>-NNN` または雛形の `TPL-<階層>-NNN`） |
| `title` | 図書名。図書名は本キーのみに記載し、本文へ見出しとして重ねない |
| `doc_type` | `charter` `standard` `requirements` `basic_design` `detail_design` `test` `traceability` `template` `index` のいずれか |
| `version` | `X.Y.Z` のSemVer |
| `status` | `Draft` `Review` `Approved` `Deprecated` のいずれか |
| `date` | `YYYY-MM-DD` |
| `author` | ロールIDまたは公開アカウント名。個人実名を書かない |
| `doc_standard` | 準拠する本書の版（例: `DOC-GOV-003@1.0.0`） |
| `tags` | YAMLのリスト |

## 3.2 見出しと章節項番号
1. 見出しレベルn（`#` の個数）の見出しは、n個の整数をピリオドで連結した番号を持つ。例は `# 1 本書の位置づけ`、`## 1.1 目的`、`#### 1.1.1.1 項目名` とする。
2. 番号の末尾にピリオドを付けない。番号と見出し文字列の間は半角スペース1個とする。
3. 番号は各階層で1から始まる連番とする。欠番、重複、階層飛ばし（`##` の直下に `####`）を禁止する。
4. 番号のない見出しと、丸数字による擬似見出しを禁止する。
5. フェンスドコードブロック内の行は見出しとして扱わない。
6. 図書名は見出しにせず、第1階層（`#`）を章として使う。

## 3.3 第1章の固定構造
全図書の第1章は次の見出しで固定する。

| 見出し | 記載内容 |
| :--- | :--- |
| `# 1 本書の位置づけ` | 章見出し |
| `## 1.1 目的` | 本書が存在する理由を1〜2文で記載 |
| `## 1.2 記述対象` | 本書に書く内容の箇条書き |
| `## 1.3 記述対象外と参照先` | 書かない内容と、その正本図書へのObsidianリンク |
| `## 1.4 改版履歴` | 列は 版 / 日付 / 起因PBI / 変更概要 |

## 3.4 ID定義の記法
1. IDの定義は、種別ごとに定める定義元図書の1か所のみで行う。
2. 見出し定義型（要件、機能、画面、外部I/F、モジュール、プログラム、関数、データ形式）は、見出し `<番号> <ID> <名称>` で定義し、直下に属性表（列は 項目 / 内容）を置く。属性表には `上位ID` と `状態` を必ず含める。
3. 表定義型（受入基準、入出力項目、フィールド、エラーコード、画面部品、画面遷移、テストケース、テスト結果）は、定義元図書の所定の表の第1列で定義する。
4. 他図書でのIDの参照は、定義元の見出しへのObsidianリンクで行う。
5. ID名称と名称の再掲だけの一覧表を作らない。全体把握は見出しのアウトラインで行う。

## 3.5 文体規約
1. 文体は常体（である調）とする。
2. 1文に1つの事項を書く。
3. 数値には単位を付ける。
4. 図はMermaid記法のみで描く。
5. 曖昧語と装飾語は [[#3.6 禁止語リスト|禁止語リスト]] に従い使用しない。

## 3.6 禁止語リスト
次の語は、コードブロックとインラインコードを除く本文に書かない。構文検査器は本表を読み込んで検査する。

| 禁止語 | 理由 |
| :--- | :--- |
| `適宜` | 判断基準が不明で複数の解釈ができる |
| `原則として` | 例外条件が不明である |
| `速やかに` | 時間の基準が不明である |
| `適切に` | 適否の基準が不明である |
| `十分な` | 量の基準が不明である |
| `など` | 範囲が不明である |
| `極めて` | 数値化できない誇張である |
| `比類なき` | 数値化できない誇張である |
| `美しく` | 観測できない主観評価である |

## 3.7 未確定事項のマーカー
1. 未確定事項は、仮定ID `ASM-NNN` を付けて本文の該当箇所に `【仮定: ASM-NNN】` と書く。
2. 未記入の箇所は `【TBD】` と書く。
3. 仮定と未記入は、確定時に全文検索で全件特定できる状態を保つ。

# 4 リンク規約

## 4.1 Obsidianリンクの書式
1. 他図書の見出しへのリンクは `[[<ファイル名（拡張子なし）>#<見出し全文>|<表示文字列>]]` とする。
2. 同一図書内のリンクは `[[#<見出し全文>|<表示文字列>]]` とする。
3. 見出し全文は、番号を含む見出し行の文字列と完全に一致させる。

## 4.2 リンクの制約
1. `docs/` 内の図書へのMarkdown相対リンクを使わない。
2. 外部URLはMarkdownリンクで記載する。
3. ソースコードはバッククォート付きのリポジトリ相対パスで記載する。
4. リンク先のファイルと見出しの実在は構文検査器が全件検査する。

# 5 入出力仕様の意味と形式の分離

## 5.1 意味仕様
1. 外部I/F仕様書、内部I/F仕様書、プログラム仕様書は、入出力の意味と意図を書く。
2. 入出力項目表の列は 項目ID / 名称 / 意味・意図 / 必須 / 形式参照 とする。
3. `形式参照` 列には形式仕様の `DAT-*` IDへのObsidianリンクのみを書き、型・桁・値域を書かない。

## 5.2 形式仕様
1. DB仕様書、ファイル形式仕様書、データ構造仕様書は、形式のみを書く。
2. フィールド表の列は フィールドID / 論理名 / 物理名 / 型 / 桁・長さ / 値域・書式 / 既定値 / 必須 とする。
3. 用途と意図を書かない。用途は利用側の意味仕様からの参照で表す。
4. 同一のデータ構造が、ある関数の出力であり別の関数の入力でもある場合は、両者の入出力項目表が同一の `DAT-*` IDを参照する。

## 5.3 画面仕様との関係
1. 画面仕様書は、画面の見た目と画面間の遷移関係のみを書く。
2. 画面部品に表示するデータの形式は `DAT-*` を参照し、画面仕様書へ書かない。
3. 画面から呼び出す機能の振る舞いは `FNC` と `EXT` を参照し、画面仕様書へ書かない。

# 6 雛形と構文検査

## 6.1 雛形
1. 図書別の章構造と表の列定義は、`docs/templates/tpl_<標準ファイル名>.md` の各雛形を唯一の正本とする。
2. 雛形はプロジェクト固有の値を含まない。記入箇所は `【TBD】` とする。
3. 雛形も本書の規約に従う。

## 6.2 構文検査器と適用範囲
1. 構文検査器は `.agents/skills/ipa-traceability-validator/scripts/verify_doc_syntax.py` とする。
2. 検査対象は、Frontmatterに `doc_standard` を持つ図書とする。持たない図書は対象外とする。
3. 既存図書は、新体系へ移行して `doc_standard` を付与した時点から検査対象となる。
4. 検査項目とエラーコードは、プログラム仕様書の検査器の章に定める。
