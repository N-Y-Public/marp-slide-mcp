# ページタイトル

24H365D自律開発運用の全体像とアーキテクチャ

## ページ主張

- ホスト・Docker・Antigravity・GitHubの4層が連携して自律稼働
  - 完全な環境隔離と相互牽制により、無人環境下でも安全性を死守

### 主張補足タイトル

自律開発基盤を構成する4つの責務レイヤー

#### 本文

- **ホストOS & Dockerサンドボックス**
  - **ホストOS（開発者）**: 非同期指示の入力、日報・週報の確認、全体監視
  - **Dockerサンドボックス**: `marp-slide-mcp-app` による隔離環境
  - **コマンド実行**: すべて `dev.ps1` または `docker compose run` 経由
  - **汚染防止**: ホスト環境にNode/Puppeteer依存を一切残さない
- **常駐Pythonオーケストレーター & ステートレスAIワーカー統制**
  - **常駐オーケストレーター**: `autonomous_daemon.py` が主導制御と時計監視を担当
  - **ステートレスAIワーカー**: 1工程ごとに新規 `agy` セッションを起動・破棄
  - **マルチエージェント**: 起票（`ROLE-PM`）と独立審査（`ROLE-ARCH`）を完全分離
  - **品質ゲート**: `verify_rtm.py` による4層トレーサビリティ完全保証

# ページタイトル

【起動①】常駐Pythonオーケストレーターデーモンの起動

## ページ主張

- 常駐オーケストレーター（autonomous_daemon.py）が主導して連続消化
  - 1工程ごとに新規AIセッションを起動・破棄しコンテキスト枯渇を防止

### 主張補足タイトル

STEP 5（常駐監視デーモン起動・ステートレスAIワーカー呼び出し）

#### 本文

- **常駐デーモン主導の制御プロトコル**
  - **GitHub自動監視**: `--issues-json` 省略時はGitHubのOpen Issueを自動取得
  - **並行度1件統制**: デフォルトで1度に並行着手するIssueを1件（`1`）に制限
  - **ステートレス実行**: Stage A・審査・Stage Bごとに新規セッション起動・破棄
  - **DoD自動検証**: ビルド・テスト・`verify_rtm.py` 合格時のみPR生成
  - **次Issue自動遷移**: 1件完了または保留後、停止せず次Issueへ即時遷移
- **常駐オーケストレーター起動コマンド**
  ```bash
  # 1. 常駐デーモンの起動（GitHub自動監視・並行上限1件・30秒周期）

  # 2. 1サイクル動作確認（--once / 並行数はデフォルト1件）
  docker compose run --rm app python3 scripts/autonomous_daemon.py --once --max-concurrent-issues 1

  # ※PowerShellでの実行例（改行時は `\` ではなくバッククォートを使用）:
  # .\dev.ps1 run python3 scripts/autonomous_daemon.py --poll-interval 30
  ```

# ページタイトル

【起動②】時計監視による定時レポートの決定論的自動生成

## ページ主張

- AIを介さずPython時計監視により日報3回と水曜週報を定時出力
  - トークン消費ゼロかつ遅延ゼロでdocs/reports/配下へ確実に出力

### 主張補足タイトル

STEP 6（JST時計監視・二重出力防止・手動レポート生成コマンド）

#### 本文

- **定時レポートの決定論的配信仕様**
  - **朝刊 (`07:30 JST`)**: 夜間の自律走行成果と保留判断事項
  - **昼刊 (`11:50 JST`)**: 午前の進捗状況と午後の予定
  - **夕刊 (`18:00 JST`)**: 日中帯の完了タスクと夜間走行キュー
  - **週報 (`水曜 16:00 JST`)**: 上司層向け「課題・解決・結果・宿題」
  - **二重出力防止**: `emitted_reports` 記録により同一枠の重複生成を抑止
- **定時自動監視と手動即時出力コマンド**
  ```bash
  # 常駐デーモン起動中は 07:30 / 11:50 / 18:00 / 水曜16:00 に自動出力
  # 手動で特定スロットのレポートを即時生成する場合:

  # 朝刊・昼刊・夕刊日報の手動出力
  docker compose run --rm app python3 scripts/generate_reports.py --time 07:30 --mode daily
  docker compose run --rm app python3 scripts/generate_reports.py --time 11:50 --mode daily
  docker compose run --rm app python3 scripts/generate_reports.py --time 18:00 --mode daily

  # 定例週報＋日報の手動出力 (水曜 16:00 枠)
  docker compose run --rm app python3 scripts/generate_reports.py --time 16:00 --mode both
  ```

## ページ主張

- 起票者と審査者を分離し、自己承認や曖昧要件の実装着手を阻止
  - 独立エージェントが5大判定基準で厳格にStage A→Bを審査

### 主張補足タイトル

STEP 7（起票と検証の分離・自己承認拒絶・判定フロー）

#### 本文

  - **起票ロール (`ROLE-PM`)**: PBIを作成し受入基準を定義
  - **審査ロール (`ROLE-ARCH`)**: 独立した視点で品質を客観審査

### 主張補足タイトル

STEP 9（週報テンプレート構造とプロジェクト統括への定例報告）

#### 本文

| 構成セクション | 対象読者が知りたい問い | 報告内容・記述粒度 |
| :--- | :--- | :--- |
| **1. エグゼクティブサマリー** | プロジェクト健全性は順調か？ | 全体ステータス（Green/Yellow/Red）と今週の要約 |

## ページ主張

- コンテナのハングアップやWorktreeロックは専用コマンドで復旧
  - dev.ps1のrestartやunlock機能で短時間での再開を実現

### 主張補足タイトル

TROUBLE 1（コンテナ停止・応答不全・Worktree競合の解消）

#### 本文

- **トラブル原因と復旧方針**
  - **コンテナハング**: メモリ不足や異常プロセス常駐時に発生
  - **Worktreeロック**: 異常終了時に `.git/worktrees` が残存
  - **修復方針**: コンテナの再起動および残存ロックの強制クリーン
  - **恒久対策**: 再起動後も直らない場合はキャッシュなし再ビルド
  - **所要時間**: ヘルパースクリプトにより1〜2分で復旧完了
- **復旧コマンドリファレンス**
  ```bash
  # 1. コンテナの再起動（Windows: PowerShell）
  .\dev.ps1 restart

  # 2. Git Worktreeロックの強制解除
  .\dev.ps1 unlock-worktrees

  # 3. 完全初期化（キャッシュを破棄して再構築）
  docker compose down
  docker compose build --no-cache
  .\dev.ps1 start
  ```
